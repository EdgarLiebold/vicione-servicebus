## Static follow-up gaps, not proven defects

1. **Requirement attribution is narrow:** one explicit harness variant covers real dedicated cleanup; the large DI/options and direct-harness surfaces have unit tests but no per-member/parameter requirement projection. Under `PO-2026-09-08-01` §7, every public API/new parameter needs behavior-distinguishing evidence; map or add only after the lead decides intended contract.
2. **Environment/authority boundaries:** no inspected test sets and restores all five `VICIONE_SERVICEBUS_RMQ_*` variables to discriminate host/port/management-port malformed and fallback behavior. Root and cluster safety are better tested, but IPv6 cluster authority and mid-operation cancellation/failure remain static gap candidates.
3. **Cleanup failure atomicity:** `CleanAsync` deletes listed exchanges, then queues, then invokes custom callback; no rollback is promised. Tests do not distinguish partial HTTP/delete/callback failure, retry outcome, or whether `CleanVirtualHostOnStart` remains true after such failure. Test or document the intended partial-cleanup contract before changing code.
4. **Protected extensibility/API shape:** configuration hooks and management-client override are public-to-subclasses, but tests largely exercise events and only one override. A callback/override exception or `null` client is not asserted; do not infer a guarantee from an incidental code path.
5. **Freshness and execution:** the packed reflection file can confirm a candidate signature list only; it does not bind today's seven source hashes to built bytes.
