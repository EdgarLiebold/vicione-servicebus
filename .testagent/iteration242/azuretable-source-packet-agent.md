## Concrete A+ findings / reservations

- **AT-01 — default saga partition collision, high-confidence static finding.** `AzureTableSagaRepository.Create<TSaga>(Func<TableClient>)` uses `typeof(TSaga).Name` as the fixed partition (`AzureTableSagaRepository.cs:41-44`), while `FixedPartitionSagaKeyFormatter.Format` uses only the correlation Guid for the row (`FixedPartitionSagaKeyFormatter.cs:25-29`). Two distinct saga types with the same simple class name in different namespaces, pointed at one table and sharing a Guid, therefore address the same entity. The public explicit-formatter overload can avoid it, but the documented default does not provide unique type identity. Reproduce with two such types on one table; the Lead must choose a stable, noncolliding default or require explicit table/partition identity. Do not silently switch to CLR `FullName` without assessing rename stability and persisted-data implications.
- **AT-02 — per-call cancellation ambiguity, static API candidate.** `AzureTableSagaLoadContext.LoadAsync` checks its `cancellationToken` once at line 30, then passes the context's `CancellationToken` to `GetEntityIfExistsAsync` at lines 33-38. If a caller's per-call token is distinct and is canceled after the initial check, it cannot cancel the pending Azure read. The XML documentation explicitly describes this behavior, so this is not asserted as a defect without the adjacent `ILoadSagaRepositoryContext<TSaga>` contract. Decide whether the API promises per-call cancellation; then either propagate/link the token or make the lifetime-only contract unambiguous and test both tokens.
- **AT-03 — bounded-journal edge proof, not a diagnosed product defect.** `AzureTableMessageJournalStore.AppendAsync` forms one update + removals + add transaction (`AzureTableMessageJournalStore.cs:65-97`) under a hard 98-row read cap (`:134-154`); `MessageJournalRecord` independently enforces per-property bytes (`MessageJournalRecord.cs:86-105`). The static design is coherent, but A+ needs direct owner tests for 98-existing-row replacement with exactly 100 actions, 99th-row fail-closed with no new entry, concurrent lease creation, and an over-limit serialized metadata/header property while the configured total entry limit does not mask that branch. The existing API member mapping already marks some append/repair boundaries partial; this packet makes no green-test claim.
