Reuse the 32-assembly denominator and deduplicating Cobertura aggregator; instrument provider suites before claiming all-test coverage. 2. For each high-risk method, read its production path and tests, then write an explicit behavior checklist and pseudo-mutations before editing. Do not add tests that only execute a line or assert implementation calls.

4. Build and run the narrow EF test project with an actual nonzero test count. Review every new assertion against the production contract, then run focused coverage and CRAP for this owner. Use a causal mutation where safe to show at least one new test fails on a single product defect.
5. Continue by risk and owner, with provider suites instrumented before deciding that their 0%-unit methods need new tests. Perform `test-gap-analysis` and `assertion-quality` on every added packet. After coherent iterations, request read-only adversarial review, run applicable full gates, and record current-byte line/branch/CRAP results.

The second packet tests JSON-converted EF properties through SQLite. One test mutates a nested list and checks change tracking plus a reload. One checks structural equality, hash consistency, and an independent snapshot from EF model metadata. Two red tests cover a serializable field omitted by custom `IEquatable<T>` and a shallow `ICloneable` snapshot; the fix must make EF track the JSON value actually persisted. Keep tests only when their assertions would distinguish a plausible product defect.

Acceptance is product behavior plus measured risk disposition. A raw line/branch percentage or a lower CRAP score alone never approves a test.
